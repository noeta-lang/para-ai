# AGENTS.md

Guidance for coding agents working in this repo — the standalone repo of the **para/ai** Noeta package (an agent harness: the provider codec seam, the run loop, tool calling, and GenAI telemetry; pure Noeta). Toolchain issues (the language, the `noeta` binary, `std.*`) belong in the monorepo at github.com/noeta-lang/noeta, not here; `para/api` issues belong in its own repo.

**`DESIGN.md` is the spec.** It is the whole plan, phase by phase, with the reasoning behind each decision and the questions that were settled. Read the section you are about to touch before touching it, and if a language limitation forces a change, say so rather than diverging quietly.

## Repo layout

- `noeta.toml` — the package manifest (`name = "para/ai"`). **No `native` key: this package is pure Noeta.** The `[trust] native = ["para/api"]` line authorizes the *dependency's* native half, not ours.
- `ai.noe` — `para.ai`: the data model (`Message`/`Part`/`Role`/`Conversation`/`Run`), `AgentConfig`, `Agent<P: Provider>`, the run loop, `AiError`, the GenAI telemetry emitted from the loop, and the streaming surface (`Event`, `EventSink`, `Frames`, `Streamer`, `HttpStreamer`).
- `provider.noe` — `para.ai.provider`: the `Provider` and `StreamDecoder` traits, `ModelRequest`/`ModelReply`/`Wire`/`Framing`/`Usage`/`StopReason`, the `Delta` accumulator (`fold`), and the shared codec utilities (recoverable JSON, base64, usage merging).
- `tools.noe` — `para.ai.tools`: the `Tool`/`Arg` attributes, `ToolSpec`, the `ToolSource` trait, `Local` (reflection over `#[Tool]`), `Toolbox`, `Type` → JSON Schema, argument coercion, and bounded concurrent `dispatch`.
- `prompt.noe` — `para.ai.prompt`: the `@prompt` **expression tier** (`@tier(prompt, text: "markdown", expr: Prompt)`), its handler `render`, the lazy `Prompt` (statics + hole thunks) and the resolved `Resolved` (statics + evaluated holes). It imports nothing else in the package, deliberately: `ai.noe` imports *it*, never the reverse.
- `mcp.noe` — `para.ai.mcp`: the MCP **client**. The JSON-RPC document layer, the `Transport` seam with `Stdio` (over `os.spawn`) and `Http` (streamable HTTP: POST over a `para.api.Api`, plus the `Events` seam for the server→client SSE channel), `McpClient` with `impl ToolSource`, resources, prompts, and the `Sampler` seam. Its suite spawns a POSIX-shell MCP server it writes to a temp path — the round trip is real, and nothing depends on a published server.
- `anthropic.noe` — `para.ai.providers.anthropic`: the Anthropic Messages API codec.
- `openai.noe` — `para.ai.providers.openai`: `OpenAiCompat`, the parameterized Chat Completions codec, plus `OpenAi`, `OpenRouter`, and `OllamaCompat` — **field-less structs holding only constructors that return an `OpenAiCompat`**. None of the three declares a `Provider` impl; there is one codec. Add a compatible vendor with `OpenAiCompat.at(url, key, vendor)`, not a file.
- `google.noe` — `para.ai.providers.google`: the Gemini `generateContent` codec.
- `ollama.noe` — `para.ai.providers.ollama`: Ollama's **native** `/api/chat` codec, over NDJSON. A second door onto the server `OllamaCompat` reaches through `/v1`, and it exists because `keep_alive`, `options`, `think`, per-message `images`, and a reply's `thinking` have no OpenAI-compatible spelling.
- `mock.noe` — `para.ai.mock`: the scripted `Mock`, which is a `Provider`, a `para.api.Middleware` (the buffered transport) **and** a `para.ai.Streamer` (the streamed one), plus `Collector`, `ScriptedFrames`, and `Replay`.
- `agui.noe` — `para.ai.agui`: the AG-UI encoding of `para.ai.Event` (`encode`, `encode_all`, `wire_of`), the `RunAgentInput` decoder (`RunInput`, `Context`, `ClientTool`), and the responder — `respond(agent, req)` / `respond_to(agent, input)` over `std.http.server.sse`, the `FrameOut` seam with `Live` and the `Tape` collector, and `stream_sync` for driving a whole session from synchronous code. It is the one module that imports `para.ai.mock` at top level; see the note in its header for why that cannot be a block-scoped import.
- `guard.noe` — `para.ai.guard`: the `Guard` trait, `Stage`, `Verdict`, `GuardCtx`, `OnDeny`, `Fired`, the `decide` walk, and the nine standard guards (`ToolAllowlist`, `Approval`, `MaxTurns`, `TokenBudget`, `Redact`, `Blocklist`, `SchemaGuard`, `Recall`, `Judge`). It knows nothing about the run loop; `ai.noe` owns the four points a guard is consulted at and what `AgentConfig.on_deny` does with a `Deny` at each of them.
- `examples/*/` — each a standalone package depending on this repo via `para = { path = "../.." }`. `ask` is the phase-1 surface; `tools` is the phase-2 tool loop; `memory` is the phase-6 MCP client, with a memory server in POSIX shell beside it; `prompt_cache` is the phase-8 `@prompt` tier and the cache breakpoint; `structured` is the phase-5 `extract::<T>` with a `Validate` invariant, a repair round and a denying guard; `agui` is the phase-7 AG-UI server, and the only example that binds a port (from `noeta run`; its suite binds nothing); `providers` is the phase-4 five-vendor selection, and it is the **only place in the repo that opens a socket** (see the live-Ollama note below). Phase 3 added no example; the streaming surface is covered by the package's own suite, and DESIGN's `chat-cli` is the natural home for one. **An example directory name must be a valid package identifier** — `prompt-cache` is rejected (`` `company` and `package` must each be identifiers ``), hence `prompt_cache`.
- `.github/workflows/` — CI (`ci.yml`) and the tag-triggered registry publish (`release.yml`).

### Why the files are flat

DESIGN.md §16 sketches `providers/anthropic.noe`. The files are at the repo root instead, with the design's **namespaces** unchanged (`anthropic.noe` declares `namespace para.ai.providers.anthropic`). The reason is the module loader: a dependency package is walked recursively, but an entry file's sibling scan is **flat**, so a `.noe` file in a subdirectory can neither see its siblings one level up nor be linked when `noeta check`/`noeta test` runs it as an entry. That would make the package's own `@test` blocks unrunnable. Namespaces are declaration-based, so nothing about the public surface depends on the path — put new modules at the root and give them the namespace DESIGN.md names.

## Build & test

Pure Noeta — no cargo anywhere in this repo. But note:

- **A `git worktree` needs no special setup.** `para/api` resolves from the registry (`{ version = "^0.2", package = "para/api" }`), so a worktree under `.claude/worktrees/` resolves it exactly as the repo root does. This was a path dependency on `../para-api` until `2026-08-01`, which a worktree resolved to a non-existent `.claude/worktrees/para-api` and which needed a local symlink to work around; the dependency and the workaround went together.
- **The first `noeta check` composes a toolchain** (several minutes), because `para/api` ships a native extension crate that has to be compiled in. Later runs reuse the cached binary. If a command seems to hang on `composing the toolchain with native dependencies [para/api]`, it is building; let it finish.
- **Do not compose two toolchains at once.** Compositions share `~/.cache/noeta/compose`, and the final link is a release LTO build; two of them racing can fail with a bare `rustc` exit 101 and no diagnostic, which reads exactly like a real compile error. Observed once here — the identical command passed on rerun with nothing else changed. If a composition fails with no error text, check whether another agent is composing before believing it. CI is unaffected: `ci.yml` runs the package and every example serially in one job.
- `noeta check <file>.noe` and `noeta test <file>.noe` at the repo root run the package's own suite — the codec fixture tables, the delta fold, the base64 vectors, the captured-SSE decoder tables, the prompt tier's decomposition and laziness probes, the MCP round trip against an in-repo shell server, and the end-to-end run-loop tests over `Mock` on both transports. **387 tests across the twelve files** (prompt 8, ai 24, provider 20, tools 37, mcp 43, anthropic 43, mock 61, openai 45, google 37, ollama 30, agui 23, guard 16), plus 14 reported `skip`s: those are the `#[Tool]` fixtures and the tier-bound test helpers, which are functions in a `@test` block and not tests (see the tier note below). `examples/ask` is 6, `examples/tools` is 9, `examples/memory` is 5, `examples/prompt_cache` is 8, `examples/agui` is 8, `examples/structured` is 8, and `examples/providers` is 10 — 54 across the seven.

- **A bare `noeta test` at the repo root walks the examples too, and `examples/memory` fails from there.** Its server path is relative (`memory-server.sh`), so a run whose cwd is the repo root spawns `sh` on a file that is not there and four tests fail with `server_exited … No such file or directory`. Run from `examples/memory` and they pass. Worth knowing before reading a root-level `4 failed` as a regression: the totals a root run reports are 440 passed / 4 failed / 14 skipped, and the four are always those.
- **Check from an example, not just from the package root.** A module that is the entry links differently from one reached through an import, and two real failures appear *only* from a consuming package: the `dyn` coercion error below, and anything this package leaks across the reflection boundary (a dev tier is active for the entry file alone, so the package's own suite cannot see its fixtures escaping). `noeta test` in `examples/ask` and `examples/tools` is the cheapest way to catch both, and a green package suite is not evidence either way.
- `noeta check` / `noeta test` in each `examples/*` directory run that example's suite.
- **Every test is hermetic, with one deliberate exception.** `Mock` is the codec and *both* transports, so no test opens a socket and none needs an API key — a streamed run replays scripted frames through the real `StreamDecoder`. A suite that needs a key is a failed suite. **`mcp.noe` and `examples/memory` extend that to subprocesses rather than breaking it**: they spawn a real child and speak real JSON-RPC over real pipes, but the child is a POSIX shell script this repo writes (`fixture_lines` in `mcp.noe`, `examples/memory/memory-server.sh`) — no network, no npm install, no published MCP server. The MCP fixture kills itself after 30 seconds, so a test that fails before `close()` leaks a server for half a minute rather than forever.
- ~~**`mcp.noe` has flaked once, under load.**~~ **Identified and closed.** The missing piece — the test name and the assertion — turned out to be `a_server_that_dies_mid_call_is_typed_and_stays_dead`, expecting `AiError.Mcp(…, "server_exited", …)` and getting `"eof"`. A process closes its file descriptors and becomes reapable in that order, so under load EOF on the child's stdout can reach the client before `try_wait` has a status, and a single poll reports a crashed server as one that merely stopped talking. `Stdio.ended` now waits a bounded moment (20 × 5 ms, paid once, at the end of a session that is already over) for the status to become observable, so `server_exited` is deterministic and `eof` means what it says: still up, no longer talking. The assertion was **not** loosened to accept both codes — "exit status 3, and here is what it said on stderr" is the diagnostic value of that whole path.

  **It flaked again, and the second cause was in the fix.** The settle loop was written with `time.sleep`, which advances a *logical* clock and returns at once — so twenty polls ran back to back in microseconds and reported `eof` for an exiting server exactly as one poll would. Measured over 30 consecutive `noeta test mcp.noe` runs: **4 failures** with `time.sleep`, **0 in 60** (40 serial, 20 under four-way parallel load) once the pause became `nap`, which is the module's real timer. The lesson generalizes past this test: **`time.sleep` is not a wall clock**, and any loop in this repo that means to wait for the outside world has to go through `nap`.

  The exception is `examples/providers`, whose last two tests talk to a **local Ollama** if one is running (DESIGN §2.1, §15: Ollama needs no key, so it is the one provider a real end-to-end check can use). They **skip** when nothing answers at `OLLAMA_HOST`, and never fail for its absence. But `noeta test` captures a passing test's stdout, so a skip is invisible in the human report — which would let the check quietly stop running. Hence `OLLAMA_REQUIRED=1`: with it set, an unreachable Ollama is a *failure* naming the host it tried, and `ci.yml`'s `local-ollama` job sets it after starting a server and pulling `qwen3:0.6b`. If you touch these, keep both halves — a skip nobody can notice and a gate nobody sets are the same thing.

  **Those two checks build their own transport, and both reasons are load-bearing.** `client.new()` has no deadline, so `Agent.from`'s default chain would let a swapped, wedged or merely slow server hang `noeta test` with no bound and no output — which is exactly what happened once, for a quarter of an hour, against a *healthy* Ollama (the cause was a toolchain bug, since fixed; the lesson is that an unbounded network call in a suite turns any remote problem into a hang). So `live_api()` sets `OLLAMA_TIMEOUT_MS` (default 120 s) and deliberately carries **no** `Retry` layer, and `live_config()` sets `with_stream_retries(0)`: a local model that missed its deadline is telling you something, and three more deadlines only delays hearing it. Second, the default model is `qwen3:0.6b` — what `ci.yml` actually pulls, rather than a default the checks are never run against — and it is a **thinking** model, so at a small token budget every token can go to reasoning and `content` comes back empty. `live_provider()` therefore asks a thinking-capable model not to think, deciding capability from what `/api/tags` reports for *that* model rather than from its name, because `"think": false` sent to a model that cannot think is a 400 rather than a no-op.

## Conventions

- **The root `noeta.lock` is committed**, like every sibling para repo's — the generated file says "it is meant to be committed" in its own header, and its one entry now names a registry release every checkout shares. It was gitignored while para/ai's sole dependency resolved through a sibling path (`source = "path"`, `path = "../para-api"`, a developer-machine layout nothing else could reproduce); that exception ended with the path dependency. The examples' locks are a different case and are never committed: they are demo sub-projects, not package roots, and regenerate on every run (`.gitignore` carries `examples/*/noeta.lock`, since `49792b5`).
- Markdown never hard-wraps lines.
- **American English** throughout — code, comments, and docs (`behavior`, not `behaviour`).
- **Conventional commits** for all commit titles. Commit each green slice as it completes, but **never `git push` without explicit authorization**. Never move a published `v*` tag — a release is a new tag.
- Implement in full — no stubs or TODOs; new functionality lands with tests. A phase that is not built is *absent*, with the seam it attaches to named in a comment — not a function that returns nothing.
- **Never declare a `#[Tool]` at module level in this package.** Reflection is whole-program: a module-level `#[Tool]` here is discovered from every consuming application and offered to that application's language model, which is a trust-boundary crossing a dependency has no business performing (DESIGN §6). The package's own fixtures live in `@test` blocks, carry `#[std.test.Skip]` so the runner does not try to call them, and are asserted absent from a consumer by `examples/tools`. Do not "fix" a resulting failure by loosening the collision check in `Toolbox` or by filtering names in `Local` — both would hide the leak rather than close it.
- Keep `README.md` and this file up to date when layout or behavior changes.

## Things the language makes you write a particular way

Collected here because each one cost a debugging round the first time:

- **A block-bodied `match` arm produces no value.** In value position every arm must be a single expression (E0055). Extract a helper rather than opening a block.
- **A `match` whose arms all `return` still "falls off the end"** (E0048). Write `return match { … }` with expression arms, or add a trailing `return`.
- **A method that never mentions `self` is an associated function** (E0047) and cannot be called on a value. Make it a module-level `fn` instead.
- **`.await` is not allowed in a synchronous `fn`.** A test that awaits `agent.run(...)` must be an `async fn`. Under a released toolchain such a test is never driven and its assertions are vacuous — see the bug list; on `lang` main it runs.
- **`json.parse` aborts on malformed input** and `json.try_parse::<T>` cannot build a `Map<string, dyn>`, so recoverable dynamic decoding goes through `provider.parse_object` / `provider.parse_value`. Never call `json.parse` on a body that came off the wire.
- **A whole-module import binds its last segment as a local name**, which collides with a field of the same name (E0020) — hence `use para.ai.provider.{Wire, …}` in `ai.noe`, where `Agent` has a `provider` field.
- **Reflection keys are qualified — except a dev tier's.** Under `namespace para.ai.tools`, `attributes_of` reports a free function's target as `para.ai.tools.shout`, and that is exactly the string `params_of`/`invoke` take — a bare `shout` finds nothing. So "does this target contain a dot?" says nothing about whether it is a method; what does is whether the key minus its last segment names a declared type (`field_specs_of(owner).len() > 0`), which is `is_method_target` in `tools.noe`. **A declaration lifted out of a `@test`/`@bench`/`@debug` block is the exception: it is keyed by its bare name**, because the namespace qualifier is applied to a module's top-level declarations and the tier block's items are still nested inside it at that point. Measured, not inferred: a `#[Mark] fn fixture_tool` in a `@test` block under `namespace probe.lib` reports as `fixture_tool` while its module-level sibling reports as `probe.lib.real_tool`, and `invoke("probe.lib.fixture_tool", …)` fails where `invoke("fixture_tool", …)` works. Harmless in practice — `last_segment` and `is_method_target` both do the right thing with a bare key — but it means `local_target(…)` in `tools.noe` is for module-level declarations only, and the qualified-key path is kept under test by the refusal probes, which stay at module level for that reason.
- **A dev tier is activated for the *entry file only*.** `noeta test other.noe` runs `other.noe`'s `@test` blocks and strips the blocks of every module it imports — a sibling in the same package and a dependency package alike. Measured both ways. Two consequences worth having: the package's `@test`-block `#[Tool]` fixtures are invisible to each other across modules (so `noeta test mock.noe` sees `mock_*` and nothing from `tools.noe`), and they are invisible to a consumer's `noeta test` as well as to its `noeta run`, which is what makes the tier a real boundary rather than a build-mode convenience.
- **`#[Skip]` needs the qualified spelling or a top-level `use`; a `use` inside the block is silently ineffective.** `#[Skip("…")]` with no import at all is a clean check error (`` `Skip` cannot be used as an attribute ``). `use std.test.{Skip}` at **top level** works. `#[std.test.Skip("…")]` inline works, and is what this package uses so that a dev-only import stays out of a shipping module's surface. `use std.test.{Skip}` **inside** the `@test` block type-checks, raises nothing, and does not skip — the fixture runs as a test and fails on its missing arguments. See the bug list.
- **`invoke` takes a positional `List<dyn>` and nothing else.** Unlike `construct`, it has no named-map form, so a *gap* — a defaulted parameter omitted while a later one is supplied — is not expressible. `bind` in `tools.noe` refuses it by name rather than guessing at the default, which reflection does not expose either.
- ~~**A module-qualified extern enum variant does not compile.**~~ **Fixed upstream, and re-measured here rather than taken on trust:** `use std.http` + `http.Framing.Sse` and `use std.http.{Framing}` + `Framing.Sse` both compile, both run, and are `==`-equal; a module can now name `std.http.Framing` and a same-named enum from another package at once, qualifying one. `Wire` **keeps** `streamed()` / `ndjson()` / `as_sse()` / `as_ndjson()` anyway, for two reasons. The first is CI: `ci.yml` pins a released `noeta`, and a simplification that compiles only on `lang` main would redden it for no behavior gain — the same rule the fixed-but-unreleased entries in the bug list follow. The second outlives the floor: `streamed()` is the run loop's one branch point stated as a predicate rather than as an enum comparison, and `as_sse()` keeps a codec from having to name two enums that share a spelling and qualify one of them. `provider.noe`'s comments already say this rather than citing the old bug, so when the floor rises there is nothing to do but delete this note.
- **A whole-module import and a same-named pattern binding disagree by scope shape.** `use std.id` binds `id`. At **top level** a later `P.Call(id, …)` arm is a clean check-time error (`binding \`id\` shadows an imported module`, with the `use … as …` fix in the help); inside a **namespaced module** the same code is accepted and runs correctly. Re-measured against `lang` `d77c222b`: an earlier version of this note claimed a run-time abort with no check-time error, and **that reproduces in neither shape** — most likely fixed by `a use binds in one file, at run time too` landing while phase 3 was in flight. The residual inconsistency is real but minor, and `use std.id.{uuid}` sidesteps it either way. Do not avoid `id` as a binding name on the strength of the old note.
- **A `dyn` coercion needs the impl written *inline in the type body*, not as a standalone `impl T for X` block** — at least once the trait is named as `dyn T` in another trait's method signature. `Provider.decoder(): dyn StreamDecoder` plus a standalone `impl StreamDecoder for AnthropicStream` makes `return AnthropicStream.new()` fail with E0007 "expected `dyn StreamDecoder`, found `AnthropicStream`" **from every entry except `anthropic.noe` itself** — so `noeta test anthropic.noe` is green and `noeta test` in `examples/ask` is not. Writing the impl as `impl StreamDecoder { … }` inside the class body fixes it completely. All five decoders in this package are written that way and say so — and `examples/providers` is what proves it, because it is the only entry that reaches every codec's `decoder()` from outside its own module.
- **A top-level binding is invisible inside a named `fn`** (E0005, with `use (NAME)` in the help). So a module constant is written as a zero-argument `fn` — `max_cache_breakpoints()` in `anthropic.noe`, `kind_text()` and its siblings in `provider.noe`.
- **A `class` field is private outside the class** (E0035) — including from top-level code in the same module. `pub mut` is the fix; `examples/prompt_cache` needs it on its recording spy so the entry-point statements can read the counter. Curiously, a class declared *inside* a `@test` block is readable from that block without `pub`, which is why the same spy pattern in `prompt.noe` and `mock.noe` needs no marker.
- **A trait cannot be implemented for a builtin type** (E0013: `` cannot implement a trait for `string`: it is not a record, class, or enum declared in this module ``). So there is no `IntoPrompt` bound spanning `string` and `Prompt`, and `AgentConfig` has two named doors (`with_system`, `with_system_prompt`) that agree on one representation instead.
- **An expression tier's handler may return any type, and a `@prompt { … }` block works inside a `@test` block and across a package boundary.** All measured on `lang` main: a `@tier(prompt, text: "markdown", expr: Prompt)` whose handler returns a struct type-checks; the block evaluates in a dev tier; and a consumer package brings the syntax into existence with a `[directives] prompt = "para/ai"` binding — noeta 0.5 made a tier *bound* rather than imported, so no `use` enables one. Statics are verbatim, including the whitespace between the braces and the body (` hi ` for `@prompt { hi }`), and `statics.len() == holes.len() + 1` holds including the empty static between two touching holes.
- **A bare `Ok(v)`/`Err(e)` assigned to an *already annotated* `mut x: Result<T, E>` is E0023** ("cannot infer the type of `x`"), anywhere in a body — the declaration's annotation is not consulted for the assignment's expected type, and the diagnostic's help suggests exactly the annotation that is already there. `?T` with `some(v)` is unaffected, which is why nothing before phase 6 met it. Assigning through a function whose *declared return type* is that `Result` types fine, so `mcp.noe` writes its `await_reply` accumulator through `settled`/`unsettled`. Minimized; see the bug list.
- **`Result<void, E>` has a payload-free `Ok`**, so a `match` arm written `Ok(x)` matches nothing and the value falls through to "no match arm matched the value Ok" at run time. Match it with `_`.
- **`echo` is a keyword**, so no function may be named that. A `#[Tool]` whose model-facing name has to be `echo` gets it from `#[Tool(name: "echo")]` — which is also a neat way to prove the collision check compares model-facing names rather than symbols.
- **A `class`'s fields are private outside the class** (E0035), including to a free function in the same module. A test helper that has to build one — an unwrap-or-fail fallback, say — needs an associated function *inside* the class (`McpClient.unstarted()`).
- **`type_name::<T>()` forwards a type parameter; the other name-keyed reflections do not.** Since noeta 0.3 a generic may ask what its own `T` is called — in a top-level `fn` *and* in a method, which is what `Output.of::<T>()` is built on. `field_specs_of::<T>()` over an erased `T` is still E0058, and the diagnostic says how to bridge it: `field_specs_of(type_name::<T>())`, because `type_name` resolves per instantiation where the compile-time `::<…>` key cannot. So a name-keyed door stays name-keyed internally (`schema_for(target)`, `Output.for_name`) and the turbofish sits at the surface. Verify before assuming a given reflection forwards — they differ.
- **A turbofish must supply every type parameter** (`f::<A>(…)` on `fn f<T, S>` is `` expects 2 type argument(s), found 1 ``), so a second parameter has to be erased behind a `dyn` trait rather than inferred — which works: a generic struct coerces to `dyn Trait` fine, given the inline-impl rule below. `extract` is `extract::<T>(agent, conv, out)` rather than `agent.extract::<T>(conv)` for that reason.
- **Expected-type seeding fills a return-only generic from an annotation, but not from a reassignment.** `mut r: Result<T, E> = make()` infers; `r = make()` two lines later reports `cannot assign Result<dyn, E>`. Forwarding the enclosing `T` into the helper's turbofish closes it — `r = failed::<T>(e)` — which a *user* generic accepts even though the reflection turbofishes above do not.
- **`construct(name, fields)` checks a field's presence and its *scalar* type, and nothing else.** A `Map` supplied for a field declared as a struct type is stored verbatim and answered `Ok`; the value survives `.as<T>()` and aborts at the first field read with `` no field `x` on map ``. Same hole `invoke` has for arguments, and `tools.noe` closes it the same way: `coerce_struct` coerces every field before `construct` sees it, and nothing reaches the builder around it. Filed upstream.
- **An enum value cannot be built from JSON at all.** `@derive(Deserialize<Json>)` on a struct with an enum-typed field is **E0050 at check time**, `construct` answers `` not a constructible struct or class ``, `json.decode_typed` needs the recipe the derive would have registered, and `Enum.from` takes a *case name* (not a backing value) and **aborts** on an unknown one. `variants_of` shipping closed the *schema* half of this and not the construction half — so an enum-typed tool parameter is still refused, and the message says which gap it is. Do not "fix" it by emitting the schema and letting dispatch fail.
- **`regex.compile` aborts on an invalid pattern and has no `try_compile`.** The `json.parse` shape with no `json.try_parse` beside it, so a pattern read from configuration cannot be validated. `Redact.new` is infallible for that reason and says so.
- **`std.tracing` has no `current_span`.** `span`, `with_span`, `span_from` and `current_context` exist; a module handed no span cannot add an event or an attribute to the one that is open. `guard.noe` opens a short child span instead, which context propagation nests in the same place.
- **A local binding that shadows a module-level `fn` fails at its first *use*, not at the binding.** `mut correction = ""` beside a top-level `fn correction(e: JsonError)` type-checks, and the error is an E0007 at `f(correction)` reading `argument of type fn(JsonError) -> string is not assignable to string`. Cost a round twice in this phase; rename the local.
- **`invoke` validates a callable's name and arity, and not its argument types.** `invoke("f", ["seven"])` against `fn f(n: int)` returns `Ok` and aborts *inside* the body. That is why `tools.noe` coerces every argument to its declared type first: the coercion layer is the type check, and nothing may reach `invoke` around it.
- **A `use` inside a `@test` block does not work for a package name** — and the failure mode differs by what you import, which is what makes it confusing. Measured three ways while writing `agui.noe`'s suite: `use std.http.client` (a whole *std* module) inside the block works; `use para.ai.AgentConfig` inside it reports ``` `AgentConfig` is not a module, namespace, or type in `para.ai` ``` at `noeta test`; and `use para.ai.mock.Mock` inside it reports `cannot find para.ai.mock.Mock in this scope` at every use site. **`noeta check` is clean for all three** — only the tier-activating run fails, which is exactly the trap. Same pass order as the `#[Skip]` entry in the bug list below: a block-scoped `use` becomes top-level only *after* tier activation, and by then the module graph has been resolved. Put a test-only package import at top level and say why it is there, as `agui.noe` does.
- **Every `fn` in a top-level `@test` block is a test root.** The runner calls each with no arguments, so a *helper* that takes one fails as a test (`` `kind_of` expects 1 argument(s), found 0 ``) rather than serving the tests. Helpers therefore live at module level, below the block — which is why `mock.noe`'s `comparable`, `text_deltas`, and `drain_events`, and `agui.noe`'s `terminals`, `is_kind`, and `payloads_of`, are outside their blocks. `#[std.test.Skip]` is the other spelling, and it is what the `#[Tool]` fixtures use, because those must stay *inside* the tier.

## Toolchain bugs — what still bites, and what stopped

Each was reproduced minimally against `lang`, originally at `7575aece` and re-measured at `d80f8184`. They are worked around here rather than papered over. Some are **fixed in `lang` main** but not in a released toolchain, and CI pins a release — so those workarounds stay until the `toolchain` floor in `noeta.toml` rises past them, at which point delete the workaround and the note together. Struck entries are fixed and their workarounds are *gone*, because keeping code that only exists to dodge a bug that no longer exists is its own kind of lie.

**Re-measure before believing an entry here.** Every claim was checked again at `d80f8184`; three that had been true were not any more, one that was described as unfixed had a regression test upstream, and two new ones showed up. An entry that says "fixed" says how it was measured.

- **An `async fn` in a `@test` block is never driven.** The runner calls it, gets a `Future`, and drops it — so `assert(false)` in one *passes*. Every assertion in an async test is vacuous. Phase 2's tool-loop tests are therefore written synchronously, over `run_sync` plus `Mock.calls()`, which sees the exact bytes of the second model call and so the whole conversation including the tool turn. `ai.noe` and `mock.noe` still carry two phase-1 `async` tests; under a stock toolchain they are vacuous. **Fixed upstream** (`lang` `8b95362c`, merged as `b8d3e236`) — the runner now `.await`s the synthesized call when the root is `async`. Verified against merged `lang` main: the whole suite here is still green and the two phase-1 async tests genuinely execute.
- ~~**`attributes_of::<T>()` sees only what the entry module *links*.**~~ **Fixed upstream** (`lang` `d80f8184`) — reflection now reaches the whole program, dependency packages included. Measured: from an app entry, `attributes_of::<Mark>()` reports `["app.side.side_tool", "probe.lib.real_tool", "entry_tool"]` — a sibling module the entry never imports, a dependency package's function the entry never imports, and its own. **The fix broke this package**, and how it broke it is the thing to remember rather than the old bug: `tools.noe` and `mock.noe` declared their `#[Tool]` fixtures at module level, so every consuming application's toolbox grew five tools it had never heard of. `examples/tools` went 8 passing to 2 failing with a toolbox of `["mock_shout", "mock_add", "shout", "add", "shapes", "weather", "distance_km"]`. **A library must not declare a `#[Tool]` at module level** — see DESIGN §6, and the fixtures now live in `@test` blocks with `#[std.test.Skip]`.
- **`break`/`continue` clobber a `mut` local assigned in the same block, inside a named `fn`.** `mut a = []; for x in xs { if p(x) { a = a ~ [x]; continue } }` leaves `a` unit on the next iteration, in both `for` and `while`, for scalars and heap values alike. Correct at top level. The drop pass reclaims the accumulator on the exit edge (`Move r0 <- r5; Drop r5; Drop r0; Jump`). `encode_messages` in `anthropic.noe` is written with `if`/`else if`/`else` for this reason; **do not add a `break`/`continue` after an assignment** while the workaround stands. **Fixed upstream** (`lang` `92aa516f`, merged as `d77c222b`) — the early-exit path now applies the same `live_out` exclusion the fall-through path always had. The `if`/`else if`/`else` in `encode_messages` can go back to `continue` once the toolchain floor rises.
- ~~**The prelude `Type` and `Semantic` enums have no expression form at runtime.**~~ **Fixed upstream** (`lang` `d80f8184`). Measured: `Type.Unit`, `Type.F64`, `Semantic.TrustBoundary` and the prelude structs all construct and run, `type_of(5) == Type.Int` is `true`, and a `Type` read off `params_of` compares equal to one built by hand (`probe_type("li") == Type.List(Type.Int)`). So a role query is `r.role == Semantic.TrustBoundary`, which is what `tools.noe` and `examples/tools` now write. The schema-refusal tests still read their `Type` values off `params_of` of real declarations — not because they must, but because a real declaration asserts what the *checker* says a signature means where a hand-built `Type` only asserts what this package believes it means. The two `json_schema` arms no declaration can reach (`Type.Unit`, `Type.F64`) are now tested by construction, which they could not be before.
- ~~**`noeta mcp`'s `reflect` does not report a role conferred by a *dependency's* `@role` attribute.**~~ **Fixed upstream.** Measured over a real MCP session against a two-package probe: `reflect` returns `probe.lib.real_tool → Semantic.TrustBoundary` with the declaring file and span, alongside the entry's own. `lang` carries the regression test (`reflect_sees_a_role_conferred_by_a_dependency_package` in `crates/noeta-mcp/src/introspect.rs`) and `analyze::prepare` now resolves `noeta.toml` dependency packages. **Careful measuring this one:** the *release* binary in a `lang` checkout may predate the fix and will reproduce the old behavior exactly (attributes listed, `roles` empty) — check its mtime against the commit before concluding anything.
- **A standalone `impl Trait for Type` is invisible to `dyn` coercion when its module is not the entry** — see the gotcha above for the shape and the fix. **Still reproduces at `d80f8184`**, re-measured by hoisting `AnthropicStream`'s inline `impl StreamDecoder` out into a standalone `impl StreamDecoder for AnthropicStream`: `noeta check anthropic.noe` is clean and `noeta check` in `examples/ask` reports E0007 "expected `dyn StreamDecoder`, found `AnthropicStream`" at `return AnthropicStream.new()`. Bisected in this package rather than reduced: removing `fn decoder(): dyn StreamDecoder` from the `Provider` trait makes the standalone impls resolve again, and writing the impls inline makes the trait method fine. A three-file reduction (trait in one module, class plus standalone impl in another, a second trait naming `dyn T`, a generic struct bounded by it, an entry importing everything) did **not** reproduce, so something more of this package's shape is involved. Worth reducing properly before filing.
- **A `use` inside a `@test` block resolves an attribute's name without making the attribute work.** Found while moving the `#[Tool]` fixtures into the dev tier, and silent, which is what makes it worth writing down. Three spellings, all measured:

  ```noeta
  @test {                            //  (a) no import: clean check error,
      #[Skip("…")]                   //      "`Skip` cannot be used as an attribute"
      fn f(text: string): string { return text }
  }

  @test {
      use std.test.{Skip}            //  (b) block-scoped import: NO diagnostic, and NO skip —
      #[Skip("…")]                   //      the fixture runs as a test and fails on its
      fn f(text: string): string { return text }   //  missing argument
  }

  @test {
      #[std.test.Skip("…")]          //  (c) inline qualification: works
      fn f(text: string): string { return text }
  }
  ```

  A top-level `use std.test.{Skip}` also works. The cause is pass order: the runner matches the attribute's **qualified** name (`std.test.Skip` — `noeta_ast::reflect::TEST_ATTR_SKIP`), the loader's qualifier builds its rename map from a module's *top-level* imports, and the block-scoped `use` only becomes top-level after tier activation, which runs later. It is not a general block-scoped-`use` failure: ordinary code through one works (`use std.math` inside a `@test` block, then `math.abs(-3)`, passes). Not fixed at the source: it does not block — (c) is a documented spelling, not a workaround — and the fix is in the loader's import-map construction, which decides linking and merging, so it wants `lang`'s own suite, and a fresh worktree build of that tree is the expensive part. Filed in `lang`'s `plans/backlog.md` (branch `docs-test-attrs-not-prelude`), together with a `docs/Attributes-and-Reflection.md` fix: that page called the test attributes "prelude", which is what sends you looking for a spelling that does not need an import.
- **The *debug* `noeta mcp` overflows its stack on every file in this repo.** `check`, `symbols`, `module_graph`, and `reflect` all die with `thread 'tokio-rt-worker' has overflowed its stack / fatal runtime error: stack overflow, aborting`, killing the server mid-session; a small two-package probe is fine, so it is the size of these files (36–75 KB) rather than their shape. The **release** binary handles them. `run_stdio` builds its runtime with `tokio::runtime::Builder::new_multi_thread()` and no `thread_stack_size`, so the workers get tokio's 2 MB default and an unoptimized recursive walk exhausts it. Use `target/release/noeta` for `noeta mcp` against this repo, and read the debug-build crash as "not enough stack", not as "your program is broken" — but check that the release binary is not older than the `lang` commit you mean to measure, or you will measure a toolchain from before the fix you are testing. Filed in `lang`'s `plans/backlog.md` (branch `docs-test-attrs-not-prelude`).
- ~~**A module-qualified extern enum variant is an unlocated VM internal error.**~~ **Fixed upstream** — see the gotcha above, where the re-measurement and the `Wire`-accessor decision live.
- **The process doors are unrecoverable where every failure is remote-input-shaped.** Two of them abort the whole program, measured at `d80f8184`:

  ```noeta
  p = os.spawn("definitely-not-a-binary-xyz", [])   // E0021 spawn: cannot start … (No such file or directory)
  p.write("hi\n")                                   // E0021 write: Broken pipe   (after the child exited)
  ```

  Both are ordinary conditions for an MCP client — a server that is not installed, and a server that crashed mid-call — and a library whose contract is "a failing tool is a turn, not an outage" cannot call either blind. `mcp.noe` works around both: `Stdio.start` resolves the command against `PATH` itself before spawning, and every `send_doc` is preceded by a `try_wait` liveness check. The residual race in the second (the child dying between the check and the write) cannot be closed by that shape.

  **The recoverable doors this entry asked for have landed, and `mcp.noe` does not use them yet.** Measured on `lang` main: `os.try_spawn("definitely-not-a-binary-xyz", [])` answers ``Err(spawn: cannot start … No such file or directory)`` instead of aborting, and `p.try_write("hi\n")` to an exited child answers ``Err(write: Broken pipe)``. So `resolve_command`'s PATH walk and the `try_wait`-then-write dance are both retirable, and retiring the second is what actually closes the race — a `try_write` that loses is an `Err`, not an abort. Left for its own change rather than folded into an unrelated one; when you do it, `resolve_command` is `pub` and the refusal message ("an MCP server that is not installed is a configuration error, not a tool failure") is the part worth keeping.
- **A bare `Ok(v)`/`Err(e)` does not take its type from an annotated `mut` binding** — E0023, reproduced in eight lines:

  ```noeta
  fn f(): Result<int, string> {
      mut answer: Result<int, string> = Err("start")
      answer = Ok(3)          // E0023 cannot infer the type of `answer`
      return answer
  }
  ```

  The help says "annotate it", which the code did. `?T`/`some(v)` is unaffected; assigning through a function with a declared `Result` return type is the workaround (`settled`/`unsettled` in `mcp.noe`). A checker fix, in the assignment's expected-type propagation.
- ~~**A streamed model call after a buffered one hangs forever.**~~ **Fixed upstream** — and worth keeping, because the shape of it will fool you twice. `examples/providers` never finished against a live Ollama: the server logged exactly one `/api/chat` and then sat idle, and `noeta test` printed nothing at all, so it read as "the model is slow" or "the isolate scheduler parked" — the entry below being the obvious suspect. It was neither. The suite's `ollama_reachable()` probe makes an ordinary `GET /api/tags`, which leaves a pooled connection in `RealHost`'s reqwest client; `client.stream(…)` then runs on its own thread with its own runtime and was handed *that* connection, whose hyper driver task belongs to the host's runtime and only turns inside a `block_on` nobody was in. The request bytes were never written and `send()` never resolved — no error, no timeout, no data. Measured on the socket: 62 bytes out, 984 in, both from the earlier `GET`, nothing for the next thirteen minutes. Reduced to eight lines of `std.http` with no model call and no test runner (`api.get(…)` then `client.stream(…)` to the same origin), which is what made it obviously a toolchain bug rather than this package's. **Two lessons that outlive the fix:** a live check with no deadline turns any remote problem into a silent hang (hence `live_api()` above), and "the server logged one request and went quiet" is evidence about *the client*, not the server — check `ss -tnie` for bytes actually sent before believing anything else.
- **A blocked native read parks the whole scheduler.** Measured while deciding the MCP timeout story, and it is what decides it. Every row was **re-measured against `lang` main** once cancellation became real, because one of them used to say the opposite:

  | probe | result |
  | --- | --- |
  | `spawn watchdog(...)` (same isolate) beside a blocked `p.read_line()` | the watchdog never runs — a child silent for 3 s and then speaking is read at 3 s rather than killed at 300 ms. **Still true** |
  | `isolate watchdog(...)` beside the same blocked read | fires at its deadline and kills the child; the read returns `none` at once |
  | ~~`h.cancel()` on a parked isolate is a no-op that still reports `Err(Cancelled)`~~ | **No longer true.** An isolate sleeping in 5 ms slices, cancelled 60 ms into a 3 s deadline, joins `Err(Cancelled)` at once and the code past its loop never runs — its side effect never lands |
  | an `os.Process` passed to an `isolate` | E0042 `an isolate argument of type Process is not Send`, so a watchdog kills by pid through `kill(1)`. **Still true** |
  | `concurrent { … }` inside a synchronous `fn` | E0040 — so an isolate is reachable from a sync door only through `map_bounded` |

  Together these mean a synchronous API cannot bound a blocking child read without killing the child, from an isolate, by pid — which is exactly what `Stdio.with_deadline` does, and why it is opt-in. **Two documented limits of cancellation ride along, and the second is why the watchdog sleeps in slices at all:** it cannot preempt a native call, and an isolate parked in *one long* `sleep` observes a cancel only when that sleep ends. A whole-deadline sleep would therefore make the disarm cost the whole deadline on every reply that arrived in time. **The clean fix for the first row has landed, and this module has not taken it yet.** `Process.read_line_async` exists, and a bounded read really is an ordinary `race` with it — measured, eight lines, no isolate, no pid, no `kill(1)`:

  ```noeta
  concurrent {
      r = spawn p.read_line_async()
      t = spawn timer(ms)              // sleep(ms).await, returning none
      first = race([r, t])             // some("hi") at 100 ms, or none at the deadline
  }
  ```

  A child that answers at 100 ms yields its line; one that says nothing for 30 s comes back `none` at 400 ms. That would let `Stdio.with_deadline` drop the isolate, the pid, the `kill(1)` and the POSIX dependency, and kill through the handle it already holds — leaving `map_bounded` as the only bridge, still needed because `ToolSource.call` is synchronous. It is a rewrite of the whole deadline rather than a simplification of it, so it wants its own change and its own re-measurement of what "terminal" means; it is not blocked on anything.
- ~~**`std.http`'s `FrameStream` exposes no response status.**~~ **Fixed upstream, and the fix is the one this repo asked for.** Measured at `lang` `561daa82`: `FrameStream` now carries `status()`, `ok()`, `header(name)`, and `error_for_status()`, all readable from the opening handshake **before** the first `recv()` — `crates/noeta-stdlib/src/http_stream.rs` declares all four, and the registry prose names the rate-limit case verbatim ("a rate-limited provider answers a streaming request with a `429` whose body is a JSON error document, and since that is not an event stream, `Framing.Sse` decodes it to zero frames").

  **`mcp.noe` uses it; the provider streaming path still does not, and that is a sequencing decision rather than an oversight.** `HttpEvents.drain` (the MCP server→client channel) calls `client.stream` directly and reads `status()`/`ok()` before consuming a frame, which is why a 405 there is an empty answer and every other non-2xx is a typed failure. The model-call path cannot follow it yet: `para.ai.Streamer.open(req, framing): Result<dyn Frames, AiError>` has nowhere to put a status, so surfacing it means changing that trait, `HttpStreamer`, `LiveFrames`, `Mock`, and `Replay` — phase-3 surface, in files two other phases were editing at the time. Until that lands, every codec's `finish()` still says the truth: `HttpStreamer` calls `client.stream(req, framing)?` and drops the head, so a streamed 429 really does reach a decoder as an empty stream. **When you do it:** `Streamer.open` returns the status alongside the frames (or `error_for_status()` folds it into the `Err` arm), the run loop hands a non-2xx body to `provider.decode_error(status, body)` exactly as the buffered path already does, and the four `finish()` messages lose the clause explaining why they cannot tell. That also makes the streaming retry act on a vendor's `Retry-After` instead of only on transport failures.
